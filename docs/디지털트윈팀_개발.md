- **Vercel은 웹 화면 파일만** 내려줍니다. 데이터 통신은 브라우저가 직접 합니다.
- **영상과 드론 조종은 Pixel Streaming**(브라우저 ↔ UE5)으로 합니다.
- **점검 스크린샷은 UE5가 서버로 직접 보냅니다.** 스트리밍 영상은 압축되어 가는 균열이 뭉개지므로, 「점검」 순간의 원본 화면을 UE5가 `POST /inspections/{id}/detect`로 보내고 결과를 Pixel Streaming으로 웹에 전달합니다. 서버 주소는 UE5 실행 인자 `-CrackApiUrl`로 받습니다.
- **드론 점검 화면은 로컬 Next.js(`http://localhost:3000`)에서만** 엽니다. Vercel의 https 페이지에서는 내부망 `ws://` 연결이 차단되기 때문입니다.
- **Vercel 배포본은 대시보드(목록, 3D 마커) 확인용**이며, 터널 주소로 서버에 접속합니다.

### 1-4. 연결 약속

#### ① Pixel Streaming 메시지 (웹 ↔ UE5)

드론 이동(키보드·마우스)은 Pixel Streaming이 UE5에 그대로 전달하므로 **별도 메시지가 없습니다.**

| 방향 | `type` | 용도 |
|---|---|---|
| 웹 → UE5 | `capture` | 점검 요청 (점검 번호 포함) |
| UE5 → 웹 | `capture_result` | 드론 위치·각도, 카메라가 가리키는 벽면 좌표, 벽까지 거리, 화각. **바로** 보냄 |
| UE5 → 웹 | `detect_result` | 서버 `detect` 응답 본문을 **그대로** 전달 (형식은 ② 참고) |
| UE5 → 웹 | `detect_error` | 서버 전송 실패 |
| 웹 → UE5 (선택) | `goto` | 대시보드에서 고른 균열 위치로 드론 이동 |

```json
// 웹 → UE5
{ "type": "capture", "id": "c-0001", "inspectionId": 3 }

// UE5 → 웹 (바로)
{
  "type": "capture_result",
  "id": "c-0001",
  "structureId": 1,
  "drone": { "x": 820.0, "y": -150.0, "z": 400.0, "yaw": 90.0, "pitch": -5.0 },
  "hit":   { "x": 1250.0, "y": -150.0, "z": 380.0 },
  "hitNormal": { "x": -1.0, "y": 0.0, "z": 0.0 },
  "hitOk": true,
  "distanceCm": 430.0,
  "fovDeg": 90.0
}

// UE5 → 웹 (서버 응답 후) : 서버 응답 본문 그대로
{ "type": "detect_result", "inspectionId": 3, "captureId": "c-0001", "cracks": [ ... ] }

// UE5 → 웹 (서버 전송 실패)
{ "type": "detect_error", "id": "c-0001", "status": 422, "message": "서버 응답 본문 또는 오류 내용" }

// 웹 → UE5 (선택)
{ "type": "goto", "x": 1250.0, "y": -150.0, "z": 380.0 }
```

| 필드 | 설명 |
|---|---|
| `id` | 웹이 만든 요청 번호. UE5는 받은 값을 그대로 돌려줌 (`detect_result`에서는 `captureId`) |
| `inspectionId` | 웹이 `POST /inspections`로 받은 점검 번호. UE5는 이 번호로 서버에 업로드 |
| `structureId` | 레벨에 설정된 구조물 번호 (시연은 `1`) |
| `drone` | 드론 위치(cm), `yaw`·`pitch` 각도(도). 서버가 균열별 위치를 계산할 때 사용 (카메라 roll은 0으로 가정) |
| `hit` | 카메라 정면으로 쏜 Line Trace가 벽에 맞은 좌표(cm) |
| `hitNormal` | Line Trace가 맞은 벽면의 방향 (Hit Result의 **Impact Normal**, 길이 1, 벽에서 바깥쪽). 비스듬히 찍은 사진에서도 균열 위치를 정확히 계산하는 데 사용. **선택** (없으면 벽을 정면으로 찍었다고 가정) |
| `hitOk` | 벽에 안 맞으면 `false` → 웹은 「구조물을 향해 주세요」 표시 |
| `distanceCm` | 카메라에서 벽까지 거리(cm) → **균열 크기를 mm로 환산할 때 사용** |
| `fovDeg` | 카메라 **가로** 화각(도) |
| `status` | (`detect_error`) 실패 원인. 서버 HTTP 상태 코드(예: `404`, `422`) 그대로, 또는 UE5가 정한 아래 값 |

**`detect_error`의 `status` 값**

| 값 | 누가 | 의미 | 웹 표시 (예) |
|---|---|---|---|
| `0` | UE5 | 서버에 연결하지 못함 (주소·방화벽·네트워크) | 「UE5가 서버에 연결하지 못했습니다」 |
| `409` | UE5 | 이전 점검을 아직 업로드·분석 중이라 이번 요청을 거절함 | 「이전 점검을 처리 중입니다」 |
| `404`, `422`, `500` 등 | 서버 | 서버가 돌려준 HTTP 상태 코드 그대로 (`message`에 서버 응답 본문) | 「분석 실패」 + `message` |

**재점검 규칙 (한 번에 하나만)**
- 웹은 「점검」을 누르면 버튼을 끄고, 그 `id`의 `detect_result` 또는 `detect_error`를 받으면 다시 켭니다. `capture_result`의 `hitOk`가 `false`면 바로 다시 켭니다.
- 웹은 70초 안에 결과가 안 오면 버튼을 다시 켭니다 (UE5 업로드 제한 시간 60초 + 여유).
- UE5는 업로드·분석 중에 `capture`가 또 오면 **아무것도 하지 않고** `detect_error`(`status: 409`, `id`는 거절한 요청의 `id`)를 보냅니다.
- 70초가 지난 뒤 늦게 온 `detect_result`는 **오버레이를 띄우지 않고 균열 목록만 새로고침**합니다 (서버에는 이미 저장됨).

**점검(`inspection`) 단위**
- 드론 한 번 비행 = 점검 1회입니다. 웹은 `/inspect` 화면에서 **첫 「점검」 클릭 때 `POST /inspections`를 1번** 호출하고, 그 화면에 있는 동안 같은 `inspectionId`를 씁니다. 화면을 나가면 그 점검은 끝입니다.
- 「점검」을 누르지 않고 나가면 점검이 만들어지지 않습니다.

**UE5의 `capture` 처리 순서**
0. 업로드 중이면 `detect_error`(`409`)를 보내고 끝
1. `capture` 수신 → Line Trace로 벽 좌표·거리 계산
2. `capture_result`를 웹으로 전송 → **`hitOk`가 `false`면 여기서 끝**
3. 원본 화면을 JPG로 캡처 → `POST {CrackApiUrl}/inspections/{inspectionId}/detect` (`image` + `meta` = 2번 `capture_result` JSON 그대로)
4. 응답 200 → 응답 본문을 그대로 웹에 전송 (`detect_result`) / 그 외 → `detect_error` 전송

#### ② API (웹·UE5 ↔ 서버)

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/health` | 서버 상태 확인 |
| GET | `/structures` | 구조물 목록 (위험도별 균열 수 포함) |
| GET | `/structures/{id}` | 구조물 상세 (`modelUrl` 포함) |
| POST | `/inspections` | 점검 시작 `{ "structureId": 1 }` → `{ "id": 3 }` |
| POST | `/inspections/{id}/detect` | 이미지 + 메타데이터 → 균열 결과 (**UE5가 호출**) |
| GET | `/structures/{id}/cracks?severity=danger&inspectionId=3&latest=true` | 구조물의 균열 관측 목록 (위험도·점검 번호·최신만 필터 선택, 함께 사용 가능) |
| GET | `/cracks/{id}` | 균열 관측 1건 상세 |
| GET | `/cracks/{id}/history` | 같은 균열(`trackId`)의 관측 이력, 오래된 순 |
| GET | `/severity-thresholds` | 위험도 기준값 (평균 폭 mm) `{ "cautionMm": 0.3, "dangerMm": 1.0 }` |
| GET | `/structures/{id}/weather` | 구조물 위치의 현재 기온·습도·풍속 (기상청 초단기실황) |
| GET | `/files/...` | 이미지·3D 모델 파일 |
| POST | `/auth/login` | 관리자 로그인 `{ "password": "…" }` → `{ "token", "role": "admin", "expiresAt" }` |
| GET | `/auth/me` | 지금 요청의 역할 → `{ "role": "admin" \| "guest", "via": "local" \| "tunnel" }` |

**권한: 관리자 / 게스트**

| 접속 | 역할 | 할 수 있는 것 |
|---|---|---|
| 외부 사람 (QR → Vercel 웹 → Cloudflare 터널) | **게스트** | 조회(GET)만: 대시보드, 3D, 균열 상세·사진·이력, 날씨 |
| 시연 PC 로컬 웹 + 관리자 로그인 | **관리자** | 모든 기능 (점검 시작 등) |
| UE5 (로컬 네트워크) | — | `detect` 업로드 (토큰 없이) |

- 서버는 **터널을 거친 요청**(Cloudflare가 붙이는 `Cf-Connecting-Ip` 헤더)을 항상 게스트로 봅니다. 쓰기 요청은 토큰이 있어도 **403**, `/docs`는 404입니다. 터널에서는 로그인도 할 수 없습니다.
- 로컬에서 `POST /inspections`는 관리자 토큰이 필요합니다: `Authorization: Bearer <token>` (없거나 틀리면 **401**). 토큰은 12시간 유효합니다.
- `detect`는 UE5가 토큰 없이 호출합니다. 대신 터널에서는 거절합니다.
- 관리자 비밀번호와 서명 키는 `server/.env`의 `ADMIN_PASSWORD`, `AUTH_SECRET`에만 둡니다 (규칙 8). 웹 코드나 `NEXT_PUBLIC_`에 넣지 않습니다.
- 웹은 처음에 `GET /auth/me`로 역할을 확인하고, 게스트면 드론 점검 메뉴를 숨깁니다. 화면에서 숨기는 것은 편의이고, 실제 차단은 서버가 합니다.

**`POST /inspections/{id}/detect`**
- 요청: `multipart/form-data`
  - `image`: JPG 파일 (UE5 원본 화면 캡처. PNG도 가능)
  - `meta`: `capture_result` JSON 문자열 그대로
- 응답:

```json
{
  "type": "detect_result",
  "inspectionId": 3,
  "captureId": "c-0001",
  "cracks": [
    {
      "id": 12,
      "trackId": 5,
      "severity": "caution",
      "confidence": 0.87,
      "lengthMm": 420.5,
      "widthMm": 1.8,
      "areaMm2": 756.9,
      "distanceCm": 430.0,
      "fovDeg": 90.0,
      "imageWidth": 1920,
      "pos": { "x": 1250.0, "y": -162.4, "z": 391.8 },
      "bbox": [812, 400, 1104, 690],
      "imageUrl": "/files/captures/3/c-0001_orig.jpg",
      "overlayUrl": "/files/captures/3/c-0001_overlay.jpg"
    }
  ]
}
```

- `severity`: `safe`(양호, 초록) · `caution`(주의, 노랑) · `danger`(위험, 빨강)
- `pos`: **균열마다의 벽 위치**(UE5 cm). 서버가 박스 중심 픽셀을 `drone` 각도·`hit`·`distanceCm`·`fovDeg`(+ `hitNormal`)로 벽 위의 점으로 바꿉니다.
- `trackId`: **같은 균열**의 번호. 같은 구조물에서 반경 50 cm(`TRACK_MATCH_CM`) 안에 이미 관측된 균열이 있으면 같은 `trackId`를 받습니다 (길이가 2배 넘게 다르면 다른 균열). 같은 사진 안의 균열은 서로 다른 `trackId`입니다.
- 한 사진에서 같은 균열에 박스가 겹쳐 잡히면(작은 박스 넓이의 70% 이상 겹침) 신뢰도가 높은 1건만 남깁니다.
- 균열이 없으면 `"cracks": []`
- `type`·`captureId`: UE5가 이 응답을 웹에 그대로 전달하므로, 웹이 메시지 종류와 어느 요청의 결과인지 구분하는 데 씁니다. `captureId` = `meta.id`.
- 오류: 404 (없는 점검 번호), 422 (`meta` 형식 오류, `hitOk=false`, `meta.structureId`가 점검의 구조물과 다름, 이미지를 읽을 수 없음)
- `distanceCm`·`fovDeg`·`imageWidth`: 촬영 조건. 웹은 이 값으로 1픽셀당 mm를 계산해, 폭이 1픽셀보다 작으면 「측정 신뢰 불가」를 표시합니다. 값을 모르면 `null`.

**구조물 응답** (`GET /structures`는 이 객체의 배열, `GET /structures/{id}`는 1개)

```json
{
  "id": 1,
  "name": "스카이베이 경포",
  "address": "강원특별자치도 강릉시 해안로 476",
  "modelUrl": "/files/assets/structure.glb",
  "latitude": 37.8014,
  "longitude": 128.9088,
  "createdAt": "2026-10-07T07:17:27Z",
  "crackCounts": { "safe": 2, "caution": 2, "danger": 2 },
  "lastInspectedAt": "2026-11-05T07:17:27Z",
  "latestInspection": {
    "id": 1,
    "startedAt": "2026-11-05T07:17:27Z",
    "crackCounts": { "safe": 2, "caution": 2, "danger": 2 }
  }
}
```

- `crackCounts`: **실제 균열(`trackId`) 수**를 각 균열의 **가장 최근 관측 위험도** 기준으로 센 값. 같은 균열을 여러 번 찍어도 1개로 셉니다. 대시보드의 현재 상태(「긴급 조치 필요」 등)는 이 값을 씁니다.
- `latestInspection`: 균열이 1건 이상 저장된 가장 최근 점검과, **그 점검에서 찍힌 균열 수**(같은 균열을 여러 번 찍어도 1개). 해당 점검이 없으면 `null`. 빈 점검은 건너뜁니다.
- `lastInspectedAt`: 가장 최근 점검 시작 시각 (빈 점검 포함). 점검이 없으면 `null`.
- `latitude`·`longitude`: 구조물 위치 (WGS84, 날씨 조회용). 없으면 `null`.

**날씨 응답** (`GET /structures/{id}/weather`)

```json
{
  "structureId": 1,
  "temperatureC": 7.2,
  "humidityPct": 23,
  "windSpeedMs": 1.3,
  "windDirDeg": 318,
  "windLevel": "weak",
  "observedAt": "2026-11-06T20:00:00+09:00",
  "source": "KMA",
  "stale": false
}
```

- 출처: 기상청 초단기실황 (공공데이터포털). 서버가 조회하므로 **웹은 API 키가 필요 없습니다.**
- 실황은 매시 정시 기준으로 1시간마다 바뀝니다. 서버는 10분 동안 캐시합니다.
- `windLevel` (기상청 풍속 구분): `weak` 4 m/s 미만 · `moderate` 4~9 · `strong` 9~14 · `very_strong` 14 이상
- `windDirDeg`: 바람이 불어오는 방향 (0 = 북, 90 = 동). 없으면 `null`.
- `stale: true`: 기상청 오류로 마지막으로 받은 값을 보여주는 중. 웹은 「최신 정보 아님」 표시를 권장합니다.
- 오류: 404 (구조물 없음 또는 위경도 없음), 503 (서버에 키가 없거나, 기상청 오류이고 이전 값도 없음)

**균열 응답** (`GET /structures/{id}/cracks`는 이 객체의 배열, `GET /cracks/{id}`는 1개)

```json
{
  "id": 12,
  "trackId": 5,
  "inspectionId": 3,
  "structureId": 1,
  "severity": "caution",
  "confidence": 0.87,
  "lengthMm": 420.5,
  "widthMm": 1.8,
  "areaMm2": 756.9,
  "distanceCm": 430.0,
  "fovDeg": 90.0,
  "imageWidth": 1920,
  "pos": { "x": 1250.0, "y": -162.4, "z": 391.8 },
  "imageUrl": "/files/captures/3/c-0001_orig.jpg",
  "overlayUrl": "/files/captures/3/c-0001_overlay.jpg",
  "createdAt": "2026-11-06T07:17:48Z"
}
```

- 이 객체 하나는 균열의 **관측 1건**(사진 1장에서 찍힌 것)입니다. 같은 균열의 관측끼리는 `trackId`가 같습니다.
- `detect` 응답과 달리 `bbox`는 없습니다 (DB에 저장하지 않음).
- 목록은 최신순입니다.
- `?inspectionId=3`: 그 점검에서 나온 관측만. 다른 구조물의 점검 번호면 빈 배열.
- `?latest=true`: **균열(`trackId`)마다 가장 최근 관측 1건만**. 대시보드 목록·3D 마커는 이 값을 씁니다. 다른 필터와 함께 쓰면 필터를 먼저 적용한 뒤 최신 1건을 고릅니다.
- `GET /cracks/{id}/history`: 그 관측과 `trackId`가 같은 관측 전체, **오래된 순**. 폭이 시간에 따라 어떻게 변했는지 보여줄 때 씁니다.

**위험도 기준값** (`GET /severity-thresholds`)

```json
{ "cautionMm": 0.3, "dangerMm": 1.0 }
```

- 평균 폭이 `cautionMm` 이상이면 `caution`, `dangerMm` 이상이면 `danger`입니다. 값은 서버 `.env`의 `SEVERITY_CAUTION_MM`, `SEVERITY_DANGER_MM` (AI 담당이 확정, 지금은 임시값).
- 웹은 1픽셀당 mm가 `cautionMm`보다 크면 「위험도 판정을 믿을 수 없음」을 표시할 수 있습니다.

#### ③ 좌표계

| 구분 | UE5 | Three.js (웹) |
|---|---|---|
| 단위 | cm | m |
| 위쪽 축 | Z | Y |
| 좌표계 | 왼손 좌표계 | 오른손 좌표계 |

- **저장:** DB와 API는 UE5 좌표(cm)를 그대로 씁니다.
- **변환:** 웹의 `ueToThree()` 함수 한 곳에서만 합니다. 출발점으로 쓸 공식은 `(x, z, y) ÷ 100`입니다. 축 2개를 맞바꾸면 왼손·오른손 좌표계 차이가 해결됩니다.
- **검증:** glTF 내보내기 설정에 따라 축과 배율이 달라질 수 있습니다. **기준점 3개**(원점, 건물 모서리 A·B)로 반드시 확인합니다. 디지털 트윈팀이 UE5 좌표를 주고, 시스템팀이 웹에서 확인합니다.

- **실제 균열 사진을 씁니다.** AI가 실제 사진으로 학습하기 때문입니다. GPT 생성 이미지는 벽 텍스처 같은 배경에만 씁니다.
- **균열 분포:** 위험 2~3개, 주의 3~4개, 양호 2~3개 (총 8~10개)
- **배치 위치:** 시연 동선 위에, 정면과 사선 모두에서 보이게 배치합니다.
- **데칼 크기를 cm 단위로 기록합니다.** 그러면 실제 균열 폭(mm)을 알 수 있어서, AI가 측정한 값과 비교할 수 있습니다. 발표 근거로 좋습니다.
- **사진 출처 기록:** AI Hub 데이터는 이용 조건을, Roboflow 데이터는 데이터셋별 라이선스를 확인합니다.

### 2-6. `capture` 처리 (② 담당, 블루프린트 + C++)

```mermaid
flowchart LR
  A["① 메시지 수신<br/>On Input Event"] --> B["② type 확인<br/>capture일 때만<br/>id·inspectionId 저장"] --> C["③ Line Trace<br/>벽 좌표·거리"] --> D["④ capture_result<br/>웹으로 전송"] --> E["⑤ 스크린샷 JPG<br/>(C++)"] --> F["⑥ 서버 업로드<br/>POST detect (C++)"] --> G["⑦ 응답을 웹으로<br/>detect_result / detect_error"]
```

| 순서 | 내용 | 사용 노드 (UE 버전에 따라 이름이 조금 다를 수 있음) |
|---|---|---|
| 1 | 웹 메시지 받기 | **Pixel Streaming Input** 컴포넌트 → **On Input Event** 바인딩 |
| 2 | `type`이 `capture`인지 확인, `id`·`inspectionId` 저장. **업로드 중이면 `detect_error`(`409`)를 보내고 끝** (1-4 ① 재점검 규칙) | **Get Json String Value** / **Get Json Number Value**, `UCrackUploader`의 **Is Busy** |
| 3 | 카메라 위치에서 정면 방향 100m까지 선 쏘기 | **Line Trace By Channel** (시작 = 카메라 위치, 끝 = 시작 + Forward Vector × 10000) |
| 4 | 맞았으면 `hit` = Hit Location, `hitNormal` = **Impact Normal**, `distanceCm` = Distance / 안 맞았으면 `hitOk = false` | Break Hit Result |
| 5 | `fovDeg` = 카메라 컴포넌트의 **Field Of View** (가로 화각) | Get Field Of View |
| 6 | `capture_result` JSON 문자열 만들기 (1-4 ① 형식 그대로) → 웹으로 전송 | Format Text 또는 Append → **Send Pixel Streaming Response** |
| 7 | `hitOk`가 `false`면 **여기서 끝** | Branch |
| 8 | 원본 화면 JPG 캡처 → 서버 업로드 (`meta` = 6번 JSON 그대로) | 아래 C++ `UCrackUploader` |
| 9 | 업로드 결과 문자열을 웹으로 전송 | `OnDetectDone` 이벤트 → **Send Pixel Streaming Response** |

**주의**
- 숫자는 따옴표 없이 숫자로 보냅니다 (`"distanceCm": 430.0`).
- 소수점은 1자리로 반올림합니다.
- 필드 이름은 1-4 ① 표와 **글자 하나까지 똑같이** 씁니다.
- 서버 주소는 코드에 쓰지 않고 실행 인자 `-CrackApiUrl=`로 받습니다 (규칙 1).
- 스크린샷에는 UI가 들어가지 않게 합니다 (AI가 UI를 균열로 오인할 수 있음).

**C++: 스크린샷 + 서버 업로드 (예시)**

`CrackTwin.Build.cs`의 `PublicDependencyModuleNames`에 `"HTTP"`, `"ImageWrapper"`를 추가합니다.

```cpp
// CrackUploader.h
#pragma once
#include "CoreMinimal.h"
#include "Components/ActorComponent.h"
#include "CrackUploader.generated.h"

DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FOnDetectDone, const FString&, MessageJson);

UCLASS(ClassGroup = (Custom), meta = (BlueprintSpawnableComponent))
class UCrackUploader : public UActorComponent
{
    GENERATED_BODY()
public:
    // 2번: 업로드·분석 중인지. true면 블루프린트에서 RejectBusy 호출
    UFUNCTION(BlueprintPure) bool IsBusy() const { return bBusy; }

    // 2번: 업로드 중에 온 capture 거절 → detect_error(409)
    UFUNCTION(BlueprintCallable) void RejectBusy(const FString& CaptureId);

    // 8번: capture_result JSON과 점검 번호를 넘김
    UFUNCTION(BlueprintCallable) void CaptureAndUpload(const FString& MetaJson, const FString& CaptureId, int32 InspectionId);

    // 9번: 결과(detect_result 또는 detect_error JSON). 블루프린트에서 Send Pixel Streaming Response로 연결
    UPROPERTY(BlueprintAssignable) FOnDetectDone OnDetectDone;

private:
    void OnScreenshot(int32 W, int32 H, const TArray<FColor>& Pixels);
    void Upload(const TArray64<uint8>& Jpg);
    void Finish(const FString& MessageJson);
    void SendError(const FString& Id, int32 Status, const FString& Message);

    bool bBusy = false;
    FString PendingMeta, PendingId;
    int32 PendingInspection = 0;
};
```

```cpp
// CrackUploader.cpp
#include "CrackUploader.h"
#include "Engine/GameViewportClient.h"
#include "UnrealClient.h"
#include "HttpModule.h"
#include "Interfaces/IHttpRequest.h"
#include "Interfaces/IHttpResponse.h"
#include "IImageWrapper.h"
#include "IImageWrapperModule.h"
#include "Misc/CommandLine.h"
#include "Modules/ModuleManager.h"

namespace
{
    // detect_error JSON 만들기 (1-4 ① 형식)
    FString MakeErrorJson(const FString& Id, int32 Status, const FString& Message)
    {
        // JSON 문자열 이스케이프 (역슬래시를 먼저)
        FString Escaped = Message;
        Escaped.ReplaceInline(TEXT("\\"), TEXT("\\\\"));
        Escaped.ReplaceInline(TEXT("\""), TEXT("\\\""));
        Escaped.ReplaceInline(TEXT("\r"), TEXT("\\r"));
        Escaped.ReplaceInline(TEXT("\n"), TEXT("\\n"));
        Escaped.ReplaceInline(TEXT("\t"), TEXT("\\t"));
        return FString::Printf(
            TEXT("{\"type\":\"detect_error\",\"id\":\"%s\",\"status\":%d,\"message\":\"%s\"}"),
            *Id, Status, *Escaped);
    }
}

void UCrackUploader::RejectBusy(const FString& CaptureId)
{
    SendError(CaptureId, 409, TEXT("이전 점검을 처리 중입니다"));  // bBusy는 그대로 둠
}

void UCrackUploader::CaptureAndUpload(const FString& MetaJson, const FString& CaptureId, int32 InspectionId)
{
    if (bBusy)
    {
        RejectBusy(CaptureId);
        return;
    }
    bBusy = true;
    PendingMeta = MetaJson;
    PendingId = CaptureId;
    PendingInspection = InspectionId;
    UGameViewportClient::OnScreenshotCaptured().AddUObject(this, &UCrackUploader::OnScreenshot);
    FScreenshotRequest::RequestScreenshot(false);  // false = UI 제외
}

void UCrackUploader::OnScreenshot(int32 W, int32 H, const TArray<FColor>& Pixels)
{
    UGameViewportClient::OnScreenshotCaptured().RemoveAll(this);
    IImageWrapperModule& Module = FModuleManager::LoadModuleChecked<IImageWrapperModule>("ImageWrapper");
    TSharedPtr<IImageWrapper> Jpeg = Module.CreateImageWrapper(EImageFormat::JPEG);
    Jpeg->SetRaw(Pixels.GetData(), Pixels.Num() * sizeof(FColor), W, H, ERGBFormat::BGRA, 8);
    Upload(Jpeg->GetCompressed(95));
}

void UCrackUploader::Upload(const TArray64<uint8>& Jpg)
{
    FString ApiUrl;
    if (!FParse::Value(FCommandLine::Get(), TEXT("CrackApiUrl="), ApiUrl))
    {
        Finish(MakeErrorJson(PendingId, 0, TEXT("-CrackApiUrl 실행 인자가 없습니다")));
        return;
    }

    // multipart/form-data: meta(문자열) + image(JPG)
    const FString Boundary = TEXT("----CrackTwinBoundary7d1f");
    TArray<uint8> Body;
    auto AppendText = [&Body](const FString& S)
    {
        FTCHARToUTF8 Utf8(*S);
        Body.Append(reinterpret_cast<const uint8*>(Utf8.Get()), Utf8.Length());
    };
    AppendText(FString::Printf(TEXT("--%s\r\nContent-Disposition: form-data; name=\"meta\"\r\n\r\n%s\r\n"), *Boundary, *PendingMeta));
    AppendText(FString::Printf(TEXT("--%s\r\nContent-Disposition: form-data; name=\"image\"; filename=\"%s.jpg\"\r\nContent-Type: image/jpeg\r\n\r\n"), *Boundary, *PendingId));
    Body.Append(Jpg.GetData(), Jpg.Num());
    AppendText(FString::Printf(TEXT("\r\n--%s--\r\n"), *Boundary));

    TSharedRef<IHttpRequest, ESPMode::ThreadSafe> Req = FHttpModule::Get().CreateRequest();
    Req->SetURL(FString::Printf(TEXT("%s/inspections/%d/detect"), *ApiUrl, PendingInspection));
    Req->SetVerb(TEXT("POST"));
    Req->SetHeader(TEXT("Content-Type"), TEXT("multipart/form-data; boundary=") + Boundary);
    Req->SetContent(Body);
    Req->SetTimeout(60.f);  // CPU 추론은 몇 초 걸릴 수 있음
    Req->OnProcessRequestComplete().BindWeakLambda(this, [this](FHttpRequestPtr, FHttpResponsePtr Res, bool bOk)
    {
        if (bOk && Res.IsValid() && Res->GetResponseCode() == 200)
        {
            Finish(Res->GetContentAsString());  // detect_result 그대로
        }
        else
        {
            Finish(MakeErrorJson(PendingId, Res.IsValid() ? Res->GetResponseCode() : 0,
                Res.IsValid() ? Res->GetContentAsString() : TEXT("서버에 연결하지 못했습니다")));
        }
    });
    Req->ProcessRequest();
}

void UCrackUploader::Finish(const FString& MessageJson)
{
    bBusy = false;  // 결과를 보내기 전에 풀어야 웹이 바로 다음 점검을 보낼 수 있음
    OnDetectDone.Broadcast(MessageJson);
}

void UCrackUploader::SendError(const FString& Id, int32 Status, const FString& Message)
{
    OnDetectDone.Broadcast(MakeErrorJson(Id, Status, Message));
}
```

> - 위 코드는 출발점입니다. API 이름은 UE 버전에 따라 조금 다를 수 있으니 컴파일 오류가 나면 설치한 버전에 맞게 고칩니다.
> - 스크린샷은 뷰포트 해상도로 찍힙니다. 실행 인자 `-ResX=1920 -ResY=1080`을 유지합니다.
> - 스크린샷 콜백이 오지 않으면 `bBusy`가 풀리지 않아 이후 점검이 모두 409가 됩니다. 테스트 중 이런 일이 생기면 10초 타이머로 `Finish(detect_error 0)`을 부르는 안전장치를 추가하세요.
> - 서버 쪽 확인: 업로드가 되면 서버 PC의 `server/storage/captures/{점검번호}/` 에 `{id}_orig.jpg`가 생깁니다.

### 2-7. 드론 조작 (② 담당)

| 항목 | 설정 |
|---|---|
| 구조 | Pawn + **Floating Pawn Movement** + 1인칭 카메라 |
| 키 | W/S 앞뒤 · A/D 좌우 · E 상승 · Q 하강 · 마우스로 시점 |
| 속도 | 시연 영상에서 보기 좋게 느리게 (최대 3~5m/s 정도) |
| 충돌 | 켜기 (벽 통과 금지) |
| 시작 위치 | 구조물 정면 약 5m 지점 |

> 키 배치는 시스템팀 프론트 담당에게 공유합니다. 드론 점검 화면의 안내문에 들어갑니다.

### 2-8. Pixel Streaming 설정 (② 담당)

1. Pixel Streaming 플러그인 활성화 → 에디터 재시작
2. 시그널링 서버 실행 (웹 플레이어 80번, 스트리머 8888번)
3. 에디터 테스트: **Standalone Game**으로 실행하고, 추가 실행 인자에 `-PixelStreamingURL=ws://127.0.0.1:8888 -CrackApiUrl=http://192.168.0.10:8000` 입력
4. 같은 PC 브라우저에서 `http://localhost` 확인 → 다른 PC에서 `http://192.168.0.20` 확인
5. 패키징 빌드 실행 예:

```bat
:: PC 2대 (서버 PC 주소)
CrackTwin.exe -PixelStreamingURL=ws://127.0.0.1:8888 -CrackApiUrl=http://192.168.0.10:8000 -ResX=1920 -ResY=1080 -Windowed

:: PC 1대 (시연)
CrackTwin.exe -PixelStreamingURL=ws://127.0.0.1:8888 -CrackApiUrl=http://127.0.0.1:8000 -ResX=1920 -ResY=1080 -Windowed
```

> 서버 연결 확인: UE5 PC 브라우저에서 `-CrackApiUrl` 주소 뒤에 `/health`를 붙여 열면 `{"status":"ok",...}`가 보여야 합니다.

> 실행 인자 이름은 UE 버전에 따라 다를 수 있습니다. 설치한 버전의 공식 문서를 확인하세요.
